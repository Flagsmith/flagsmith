On self-hosted Flagsmith, you can store experiment events in the PostgreSQL database Flagsmith already runs on. There is
nothing extra to deploy: the SDKs send events to your Flagsmith API, which writes them to its own database, and
experiment results are computed there. Each environment has one
[warehouse connection](/experimentation/connect-a-warehouse).

## Before you start

- Self-hosted Flagsmith whose database is PostgreSQL. It isn't available on Flagsmith Cloud, and enabling it fails on
  MySQL or Oracle.
- `EXPERIMENTATION_ENABLED=true` on the Flagsmith API; the **Warehouse** tab doesn't appear without it. See
  [environment variables](/deployment-self-hosting/core-configuration/environment-variables).
- SDK versions that support experimentation; see [Run an Experiment](/experimentation/run-an-experiment#sdk-overview).

You don't need the event ingestion service, Kafka or warehouse delivery from the
[Helm chart](/deployment-self-hosting/hosting-guides/kubernetes-openshift#experimentation).

## 1. Enable it

1. Go to **Environment Settings › Warehouse**.
2. Select **Flagsmith database** and click **Enable**, then confirm.

![The Warehouse tab with the Flagsmith database card selected and the Enable button](/img/experimentation/warehouse-flagsmith-database.png)

The connection is named **Flagsmith database - _environment name_**. When you enable it, Flagsmith checks that it can
read the events table and shows **Connected** straight away. If the check fails, the connection shows **Errored** with
the reason; fix it and click **Test connection** on the card, or [contact support](/support/) if it persists.

The connection has no settings to edit. To stop storing events, delete the connection; events already stored stay in the
table.

## 2. Point your SDKs at your Flagsmith API

By default, the SDKs send events to Flagsmith Cloud. Set each SDK's events URL to your Flagsmith API URL, ending in
`/api/`, for example `https://flagsmith.example.com/api/`. Don't add `v1/events`; the SDKs append it. The connection
card shows this URL with a copy button.

![A connected Flagsmith database card showing the events URL, an SDK snippet and the Send your first event button](/img/experimentation/warehouse-flagsmith-database-connected.png)

To verify events arrive, click **Send your first event** on the connection card; the button disappears once the first
event arrives. For the rest of the setup, such as recording exposures and conversions, see
[Run an Experiment](/experimentation/run-an-experiment).

## Limitations

- Events share your application database, so they add to its size, backups and load.
- Flagsmith doesn't delete old events. Monitor the database's growth.
- For high event volumes, connect a dedicated warehouse such as
  [ClickHouse](/experimentation/connect-a-warehouse#bring-your-own-clickhouse) or
  [Databricks](/experimentation/connect-databricks).
